## 二、迭代周期规划

共划分为 **6 个开发周期（Sprint）**，每个周期建议 **3 ~ 5 天**。

```
Sprint 1 ─ 基础修复与统一规范        (3天)
Sprint 2 ─ 核心页面数据对接 - 上      (4天)
Sprint 3 ─ 核心页面数据对接 - 下      (4天)
Sprint 4 ─ 用户交互功能闭环          (4天)
Sprint 5 ─ 搜索 & 采购 & 租赁申请    (5天)
Sprint 6 ─ 体验优化与安全加固        (3天)
```

## 三、各周期详细任务

### Sprint 1：基础修复与统一规范（第 1 ~ 3 天）

**目标**：消除技术债务，统一编码规范，为后续功能开发扫清障碍。

#### 任务 1.1 — 统一 API 路径前缀

| 项目 | 内容 |
|------|------|
| **问题** | 后端存在两种路径风格：`/api/v1/xxx`（用户/分类/供应商/内容/订单/购物车）和 `/api/xxx`（商品/租赁），前端 `index.js` 与 `product.js` 调用路径也不一致 |
| **方案** | 统一所有后端 Controller 路径为 `/api/v1/xxx` |
| **后端改动** | 修改 `PmsProductController` 的 `@RequestMapping` 从 `/api/product` → `/api/v1/product`；修改 `OmsLeasingController` 从 `/api/leasing` → `/api/v1/leasing` |
| **前端改动** | 修改 `src/api/product.js` 中 axios 的 baseURL 和路径，与 `index.js` 统一使用 `/api/v1/` 前缀 |
| **验收标准** | 全平台所有 API 调用均使用 `/api/v1/` 前缀，无 404 |

#### 任务 1.2 — 清理冗余 API 定义

| 项目 | 内容 |
|------|------|
| **问题** | `src/api/index.js` 和 `src/api/product.js` 中存在两份 `productApi` 定义 |
| **方案** | 合并为一份，保留在 `index.js` 中（或重构为独立模块文件），删除重复定义 |
| **改动文件** | `frontend/src/api/index.js`、`frontend/src/api/product.js`、引用这些 API 的页面 import 路径 |
| **验收标准** | 项目中 productApi 和 leasingApi 只有唯一定义源，Mall.jsx / Leasing.jsx 正常工作 |

#### 任务 1.3 — InteractionService 层补充业务方法

| 项目 | 内容 |
|------|------|
| **问题** | `CommentService`、`LikeService`、`FavoriteService`、`ShareService` 均为空壳，仅继承 ServiceImpl |
| **方案** | 为每个 Service 补充必要的业务方法签名与实现 |
| **需新增方法** | 见下表 |

```
CommentService:
  - List<PmsComment> getCommentsByTargetId(Long targetId, String targetType)
  - PmsComment addComment(Long userId, Long targetId, String targetType, String content)
  - boolean deleteComment(Long commentId, Long userId)

LikeService:
  - boolean toggleLike(Long userId, Long targetId, String targetType)
  - boolean isLiked(Long userId, Long targetId, String targetType)
  - long countLikes(Long targetId, String targetType)

FavoriteService:
  - boolean toggleFavorite(Long userId, Long targetId, String targetType)
  - boolean isFavorited(Long userId, Long targetId, String targetType)
  - IPage<UmsFavorite> getUserFavorites(Long userId, int page, int size)

ShareService:
  - boolean addShare(Long userId, Long targetId, String targetType, String platform)
  - long countShares(Long targetId, String targetType)
```

| **验收标准** | 所有 Service 方法均有实现代码并通过编译 |

## 六、风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| mockData 页面数据结构与后端接口返回结构不一致 | 页面迁移时需大量适配 | Sprint 2 开始前先比对 mockData 字段与后端实体字段的映射关系 |
| 后端 Controller 缺少部分查询参数（如按供应商筛选商品） | 前端功能受阻 | 后端改动优先于前端页面改动，在每个 Sprint 内先做后端再做前端 |
| AI 代理接口引入额外延迟 | 用户体验下降 | 后端实现流式响应（SSE），前端逐字展示 |
| 采购模块为全新开发，工作量可能超预期 | Sprint 5 延期 | 如时间不足，可简化为仅展示列表 + 详情，暂不做发布功能 |
